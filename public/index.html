⚠️ IMPORTANT: Standard PowerShell blocks MSI installation. You MUST run PowerShell as Administrator!

Option 1: Auto-Elevating PowerShell (Triggers Admin Prompt automatically)

Paste into PowerShell — automatically triggers Windows UAC Administrator prompt:

Start-Process powershell -Verb RunAs -ArgumentList "-NoProfile -ExecutionPolicy Bypass -Command `"Invoke-WebRequest -Uri 'https://packages.wazuh.com/4.x/windows/wazuh-agent-4.9.0-1.msi' -OutFile '\$env:TEMP\wazuh-agent.msi'; Start-Process msiexec.exe -ArgumentList '/i', '\$env:TEMP\wazuh-agent.msi', '/q', 'WAZUH_MANAGER=\`"10.0.11.57\`"', 'WAZUH_REGISTRATION_SERVER=\`"10.0.11.57\`"', 'WAZUH_AGENT_GROUP=\`"GRP_MSME_FLEET_CORP\`"' -Wait; Get-Service -Name Wazuh*, Ossec* | Start-Service`""

ShieldEDR Technical Architecture Specification

Document Reference: RFC-2026-EDR-SPEC | Target Architecture: MSME Enterprise Fleets

1. System Component Overview

ShieldEDR consists of three core architectural layers:

  • Endpoint Daemon (`WazuhSvc`): Background Windows Kernel Service installed in `C:\Program Files (x86)\ossec-agent\`. Operates under LocalSystem authority.
  • Sysmon Telemetry Driver: Microsoft System Monitor driver capturing Event ID 1 (Process creation), Event ID 3 (Network socket connections), and Event ID 11 (File system operations).
  • Central SIEM Manager (`10.0.11.57:55000`): High-throughput log collection server processing JSON events over TLS v1.3.

2. MSME Department Silo Isolation

Corporate network endpoints are assigned tenant group tokens during silent installation. Data stored in OpenSearch indexers is segregated by group ID (`GRP_MSME_`).

3. Active Response Sub-Second Containment

When rule severity exceeds threshold level 10 (e.g., malicious process injection or ransomware file extension changes):

  • The active-response daemon invokes `taskkill /F /PID ` in under 500 milliseconds.
  • Adjusts Windows Filtering Platform (WFP) rules to isolate compromised hosts from the office LAN.

Operational & Network Workflow Specification

Target Domain: Active Directory & Subnet Administration

1. Active Directory GPO Deployment Workflow

Network administrators deploy ShieldEDR across corporate workstation fleets using Active Directory Group Policy Objects (GPO):

  • Create GPO in Active Directory Domain Controller (`gpmc.msc`).
  • Assign Startup Script `msme_fleet_deploy.bat` under Computer Configuration -> Scripts -> Startup.
  • Upon workstation reboot, the script installs `wazuh-agent-4.9.0-1.msi` silently (`/q`).

2. Service Verification Procedures

To verify service status on any endpoint:

  • Run `Get-Service -Name Wazuh*, Ossec*` via Administrative PowerShell.
  • Inspect `C:\Program Files (x86)\ossec-agent\ossec.log` for connection confirmation lines: `Connected to server 10.0.11.57:1514`.
