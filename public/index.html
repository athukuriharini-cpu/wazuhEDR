📚 Technical Documentation Overview

Core Security Architecture: Multi-Tenant Kernel Agent & Central Telemetry Collector

1. System Component Architecture

ShieldEDR runs an administrative kernel daemon (`WazuhSvc`) on each endpoint workstation connected to a high-throughput SIEM Manager (`10.0.11.57:55000`).

  • Sysmon Telemetry Engine: Tracks process injections, suspicious PowerShell executions, and unauthorized network sockets.
  • Sub-Second Threat Containment: Terminates malicious process IDs (`taskkill /F`) in <500ms upon rule violation.
  • Windows Filtering Platform (WFP) Firewall: Isolates infected hosts from office LAN SMB network shares.

⚙️ Operational & GPO Workflow Specification

Deployment Pipeline: Unattended Active Directory Domain Controller Mass Push

1. Active Directory GPO Mass Push

Network administrators deploy ShieldEDR across corporate workstation fleets using Active Directory Group Policy Objects (GPO):

  • Create GPO in Active Directory Domain Controller (`gpmc.msc`).
  • Assign Startup Script `msme_fleet_deploy.bat` under Computer Configuration -> Scripts -> Startup.
  • Upon workstation reboot, the script installs `wazuh-agent-4.9.0-1.msi` silently (`/q`).

2. Endpoint Service Status Verification

Verify endpoint service status via Administrative PowerShell: `Get-Service -Name WazuhSvc` (Expected: `Status: Running`).

ShieldEDR Technical Architecture Specification

Document Reference: RFC-2026-EDR-SPEC | Target Architecture: MSME Enterprise Fleets

1. System Component Overview

ShieldEDR consists of three core architectural layers:

  • Endpoint Daemon (`WazuhSvc`): Background Windows Kernel Service installed in `C:\Program Files (x86)\ossec-agent\`. Operates under LocalSystem authority.
  • Sysmon Telemetry Driver: Microsoft System Monitor driver capturing Event ID 1 (Process creation), Event ID 3 (Network socket connections), and Event ID 11 (File system operations).
  • Central SIEM Manager (`10.0.11.57:55000`): High-throughput log collection server processing JSON events over TLS v1.3.

2. Dual Firewall Engine & Network Security Mechanisms

ShieldEDR employs four distinct security and firewall control mechanisms:

  • Windows Filtering Platform (WFP) Firewall API: Dynamically modifies host firewall rules to isolate infected machines from the local office LAN during ransomware events.
  • Network Socket Telemetry (Sysmon Event ID 3): Monitors all inbound and outbound TCP/UDP connections across critical corporate ports (80, 443, 445 SMB, 3389 RDP).
  • Active Response Daemon (`ossec-execd`): Automatically executes active mitigation scripts (`taskkill /F /PID`) in under 500ms when threat rule thresholds are breached.
  • Web Application Firewall (WAF) Integration: Filters HTTP/HTTPS traffic to prevent SQL injection, cross-site scripting (XSS), and command injection against internal servers.

3. Custom URL Domain Mapping

To map a custom domain name (such as `shieldedr.com` or `shieldedr.app`) to replace `shieldedr.web.app`:

  • Go to Firebase Console -> Project Settings -> Hosting.
  • Click Add Custom Domain and type your registered domain name.
  • Add the provided A Records (`199.36.158.100`) to your domain DNS provider (Cloudflare, GoDaddy, Namecheap).
  • Firebase automatically provisions free SSL/TLS certificates for your custom domain.
